# Future learning for the Amery Ice Shelf https://doi.org/10.5281/zenodo.24520784

Code and data to reproduce our future-learning study of the Amery Ice Shelf catchment. The question
it answers: as we collect future observations of the ice sheet, how much do we learn about the
uncertain parameters of the MALI ice-sheet model — and how does that learning sharpen projections of
the catchment's contribution to sea level?

The pipeline has three parts:

1. build synthetic future observations of cumulative grounded-mass change,
2. calibrate six MALI parameters against them sequentially (NUTS), one analysis year at a time, and
3. propagate the calibrated posteriors through an emulator to project the sea-level contribution.

The paper it accompanies is listed in `CITATION.cff` and is as follows:

Zerbe, Z., Jantre, S., Urban, N. M., Hoffman, M. J., & Hillebrand, T. (2026). Future learning and uncertainty reductions in projections of the Amery Ice Shelf catchment, Antarctica. EGUsphere, 2026, 1-33.

## What's in here

- `src/`, `notebooks/` — the code.
- `inputs/` — everything the code reads: emulators, training CSVs, and the present-day posterior (~50 MB in all).
- `intermediate_data/future_observations/` — the synthetic observations the calibration targets (one
  file per configuration, generated by step 1 below and bundled so the calibrations can be reproduced exactly).
- `Project.toml`, `Manifest.toml` — a pinned Julia environment.
- `submit_packed.sh`, `mcmc_packed.slurm` — the Slurm driver for the calibration step.

Nothing generated is shipped. Running the pipeline creates `outputs/`: the raw MCMC chains, the
aggregated posteriors and sea-level projections (hundreds of GB in all), and the figures under
`outputs/plots/`. None of the figures need the raw chains once the plotting notebook has aggregated them
into `outputs/posteriors_*` and `outputs/projections_*`; the figure notebooks read only those.

## The four error-model configurations

We vary two things: whether the observation error is treated as independent in time or temporally
correlated (a discrete Wiener process), and whether the emulator's own predictive uncertainty is
included ("code" uncertainty on) or not. That gives four error-model configurations, selected by a
single letter (we say "configuration" rather than "scenario" to avoid confusion with emissions
scenarios):

| letter | error model | code uncertainty | tag |
|:---:|---|:---:|---|
| A | independent | on | `indep_code` |
| B | Wiener | on | `wiener_code` |
| C | independent | off | `indep_nocode` |
| **D** | **Wiener** | **off** | **`wiener_nocode`** (main) |

Each plotting notebook has a one-line `CONFIG` switch, so you regenerate all four the same way; the two
`Config_Comparison_*` notebooks then overlay all four.

## Setup

You need Julia (versions are pinned in `Project.toml`/`Manifest.toml`) and a Python with `numpy`,
`scipy`, `pandas`, `matplotlib`, `seaborn`, and `scienceplots` for the figures. A small conda
environment is the simplest way to provide the Python side:

```bash
conda create -n fl_env python numpy scipy pandas matplotlib seaborn
conda activate fl_env && pip install scienceplots

cd Future_Learning_Repo
julia --project=. -e 'using Pkg; Pkg.instantiate()'
```

The Julia scripts find their data relative to the repo root, so you can run them from anywhere as long
as you pass `--project=.`. The notebooks expect to be run from `notebooks/` (their paths are relative to
it) with a Julia kernel started from the activated conda environment: they read `CONDA_PREFIX` to load
the conda C++ runtime that matplotlib needs.

## Running the pipeline

**1 — Synthetic observations.** Generate the future observations for the configurations:

```bash
julia --project=. src/future_obs/AmeryFutureObservations.jl
```

(These are already bundled under `intermediate_data/future_observations/`. Figure 1 comes from the
`Future_Observation_Trajectories_Sampling.ipynb` notebook.)

**2 — Sequential calibration.** This is the expensive step (100 realizations × 19 analysis years per
configuration). On a Slurm cluster:

```bash
FL_CONDA_ENV=fl_env FL_PARTITION=<your-partition> bash submit_packed.sh D
```

`submit_packed.sh` launches independent one-node workers that pull from a shared work queue and fill
every core of every node; add `RERUN=1` to only fill in missing pieces. To run a single calibration
locally without Slurm:

```bash
# args: <job_idx 0..18 = number of analysis years>  <realization 1..100>  <output dir>
FL_SERIAL=seed9_wiener_nocode FL_ERR_MODEL=wiener FL_CODE_NOISE=0 \
  julia --project=. src/calibration/mcmc_caller_script.jl 18 1 outputs/mcmc_wiener_nocode/output_R1_local
```

**3 — Aggregate, project, and plot.** Open `notebooks/Amery_Future_Learning_Plots.ipynb`, set
`CONFIG`, and run it. It turns the raw chains into per-realization posteriors, projects them to
sea level through the VAF emulator, and draws the parameter- and sea-level-learning figures for that
configuration. `notebooks/Amery_Future_Learning_Plots_NUMBERS.ipynb` then prints the headline learning
numbers (final widths, fold reductions, best estimates) from the caches that notebook wrote.

**4 — Four-configuration comparison.** Once step 3 has been run for all four configurations,
`notebooks/Config_Comparison_Parametric_Learning.ipynb` and
`notebooks/Config_Comparison_SLE_Learning.ipynb` overlay the four learning curves — parameters and
sea-level contribution, respectively — in one figure each.

**5 — Appendix and projection figures.** `notebooks/Amery_Appendix_Diagnostics_and_SLR_Projection.ipynb`
draws the emulator cross-validation figures and the posterior-predictive sea-level distributions,
straight from the inputs.

The six calibrated parameters, in the order used everywhere, are
`vmThresh (σ_max), fricExp (q), mu_scale (C_μ), stiff_scale (C_φ), gamma0 (γ₀), melt_flux (m̄)`.

## Which notebook makes which figure

| figure | notebook |
|---|---|
| synthetic future-observation trajectories | `Future_Observation_Trajectories_Sampling.ipynb` |
| single-configuration parameter learning, sea-level-contribution learning, posterior KDEs, individual-trajectory convergence, and sensitivity figures | `Amery_Future_Learning_Plots.ipynb` (per configuration) |
| four-configuration parameter-learning comparison | `Config_Comparison_Parametric_Learning.ipynb` |
| four-configuration sea-level-contribution learning comparison | `Config_Comparison_SLE_Learning.ipynb` |
| present-day sea-level projection and the emulator cross-validation figures | `Amery_Appendix_Diagnostics_and_SLR_Projection.ipynb` |

Three supporting scripts round things out: `src/projections/regenerate_2015_slr_baseline.jl` rebuilds the
2015 sea-level baselines used by the learning plots (one per code-uncertainty convention),
`src/diagnostics/emulator_diagnostics.jl` renders the grounded-volume emulator cross-validation panels
for all 19 years, and `src/diagnostics/slr_propagation_codevar_diagnostic.jl` quantifies, for the code-on
configurations A and B, how much of the projected sea-level-contribution interval comes from the VAF
emulator's predictive variance in the final propagation step (holding the posteriors fixed).

## Inputs

Each file under `inputs/` is read by a specific stage.

- `emulators/` — the three present-day observable emulators (calving front, grounding line, mass
  balance), the 19 per-year grounded-volume emulators used for the observations and the likelihood,
  and the VAF PCA-GP emulator used to project sea-level contribution.
- `data/` — the parameter design and the RELX training ensemble, plus the grounded-volume time series
  and its per-year σ.
- `params/` — the present-day (2015) posterior that seeds everything, the 100 fixed present-day draws
  used as the generating truth and NUTS warm-starts, and the 2015 sea-level baseline.

The two parameter CSVs under `data/` serve different stages. `Amery_RELX_Ensemble_Filtered.csv` is the
training ensemble for the three present-day observable emulators — it carries the six (rounded)
parameters plus the calving-front, grounding-line, and mass-change columns, and is read by
`src/calibration/present_day_calibration.jl`. Everything downstream (the observation generator, the
likelihood, and the diagnostics) instead reads the six parameters' full-precision ranges from
`Amery_Input_Parameters_Filtered.csv` (same design, same row order).

## The Wiener error model

The observation error for the cumulative grounded-mass observations is modelled as a discrete Wiener
process, `Σ[t,t'] = σ_a² · (min(t,t') − 2016)` with `σ_a = 5.720 Gt/yr`. It has the same per-year
variances as the simpler independent model — only the year-to-year correlation is added. It appears in
two places, tagged `[WIENER]`: the observation generator (`AmeryFutureObservations.jl`) and the
likelihood (`recalibration.jl`).

## Reproducibility

The generator and calibration are single-seeded (seed 9) with BLAS pinned to one thread, so results are
reproducible across machines. Emulator predictions use the latent GP mean and variance (`predict_f`);
setting `FL_GP_PREDICT=y` switches to `predict_y`, which adds the emulators' fixed 0.01 regularizer, for
comparison. The original submission's exact synthetic observations are not bit-reproducible (they came
from an unrecorded random seed); the pipeline here uses the deterministic `seed9` observations instead.
